# Tectonic 宏伟地形

将 Tectonic **3.0.29 / Minecraft 26.3 模组版**的地形密度函数、山脉曲线、地下河、熔岩隧道、丘陵与山地表面规则适配到 Paper 的原生 `NoiseBasedChunkGenerator`，并接入地下河装饰、矿物分布与洞穴雕刻器选项。WebUI 入口为“服务器 → Tectonic 宏伟地形”。

模块直接创建具有独立生成设置的新世界，不安装数据包，不需要 Fabric、NeoForge 或 Lithostitched。原版主世界的生成设置保持原样。首次安装须完整重启，以便在玩家连接前注册固定的扩展高度维度类型。

## 平台

- 仅支持 **Paper 26.3 / Java 25**；版本、服务端品牌或原生 API 布局不符时拒绝启用生成器。已用 build 238 完成编译和离线测试，实际世界生成仍需在目标服验证。
- 使用与现有性能模块一致的 NMS 编译方式。常规构建使用固定 Paper 开发包；本地已引导的服务端可通过 `-Plbr.paperServerHome=E:/LBR-Test-26.3` 指定。
- 首次注册必须在启动阶段、主世界加载前完成；运行中首次启用会要求完整重启。模块重载不会撤销已注册的维度类型，也不会卸载已创建世界。重新启用时会核对已加载世界的实际生成器并恢复就绪状态。

使用本次集成构建更新 LunarCore 后，默认会释放内置 `lbr-terrain.jar`。如服务器关闭了 `modules.extract-builtin`，需把模块 JAR 放入 `plugins/LunarCore/modules/`，并确认 `terrain` 不在 `modules.disabled` 中；WebUI 仍需使用本次构建的核心 JAR。首次安装后完整重启。

## WebUI

可选择经典山脉、宏伟山脉、极高山脉三个 LBR 预设，以及官方默认、大型生物群系、荒漠、冰封荒原、极限地形五个上游参数预设。填写新世界名称、64 位整数种子，设置横向尺度、垂直尺度及丘陵、地下河、熔岩隧道、丛林石柱四项开关后创建。

| 总高度 | 可用 Y 范围 | 用途 |
| --- | --- | --- |
| 384 | -64 至 319 | 经典高度 |
| 512 | -64 至 447 | 冰封荒原预设 |
| 640 | -64 至 575 | 宏伟山脉 |
| 704 | -64 至 639 | 上游扩展高度 |
| 832 | -64 至 767 | 极限地形预设 |
| 1024 | -64 至 959 | 极高山脉 |

高度表示世界的总垂直空间，不保证每座山都达到上限。山峰分布仍由种子和噪声曲线决定。垂直尺度为 `0.1–15.0`，横向尺度为 `0.5–3.0`；越大的横向尺度产生越宽广的地形分布。界面以本次启动已注册的高度为准，更新后需完整重启才能注册新增档位。最低 Y 固定为 -64，不支持任意高度边界。创建后的参数不可编辑，以保持后续区块连续生成。

高级设置另有 **30 项有效参数**，由服务端返回字段、默认值和范围：

| 分组 | 参数 |
| --- | --- |
| 整体地形，2 项 | 地形抬升、超平滑地形 |
| 大陆与河流，7 项 | 海洋偏移、大陆/侵蚀/山脊噪声尺度、平坦地形偏移、地下河灯笼、地下河结冰 |
| 岛屿，4 项 | 岛屿开关、噪声尺度、倍率、偏移 |
| 海洋，2 项 | 海洋深度、深海深度 |
| 生物群系，6 项 | 温度与植被各自的噪声尺度、倍率、偏移 |
| 洞穴，8 项 | 深度截断起点与宽度、大型洞穴开关与密度偏移、细窄洞穴开关与密度偏移、雕刻器开关、扩展高度矿物分布 |
| 实验选项，1 项 | 替代侵蚀缩放 |

官方参数预设保持上游已实现字段的值。冰封荒原使用 512 总高度、1.2 垂直尺度与 0.5 地形抬升；极限地形使用 832 总高度、2.5 垂直尺度、1.6 地形抬升和超平滑地形。预设附带的未移植项会单独展示，不会作为生效参数提交。

世界名称限 1–32 位小写字母、数字、下划线或横线，必须以字母开头，不允许设备名或路径。种子通过字符串传输，保留完整 64 位精度；留空则由服务端随机生成。创建排队后可查看状态、加载、保存并卸载、请求传送在线玩家。世界有在线玩家时拒绝卸载；传送前检查出生点落脚条件，提交成功不等于玩家已经到达。

## 存档

- 登记：`plugins/LunarCore/modules/terrain/worlds.yml`。
- 世界：主存档内的 `dimensions/lbr_terrain/<世界名>/`。
- 原生生成设置：各地形世界自己的 `data/minecraft/world_gen_settings.dat`。
- 参数与原生生成图在加载时核对；缺失、损坏或不匹配时拒绝回退到原版生成。
- 同名已存在目录一律不覆盖；没有删除世界或改造现有世界的 API。
- 首次创建前记录创建意图；此后存档目录缺失时拒绝自动重新生成，需恢复备份。
- 禁用模块保留所有存档。已有地形世界仍依赖本模块在启动时注册其维度与噪声类型，不能直接移除后继续加载。

`config.yml` 中 `auto-load: true` 允许服务器启动后自动加载已登记且未手动卸载的世界。手动卸载会持久保存该世界的 `autoLoad: false`。所有管理操作写入 LBR 审计。

## 权限与接口

| 权限 | 功能 |
| --- | --- |
| `terrain.view` | 查看生成器与世界状态 |
| `terrain.manage` | 创建、加载、卸载地形世界与设置出生点 |
| `terrain.teleport` | 请求传送在线玩家 |

接口前缀为 `/api/ext/terrain`：

- `GET /status`：包含 `defaults`、`schema`、当前可用 `heights`、`presets` 与世界状态；已加载世界另含 `spawn: {x, y, z}`。
- `POST /worlds`：`{name, seed, config}`，返回 202 后查看状态。
- `POST /worlds/{name}/load`
- `POST /worlds/{name}/unload`
- `POST /worlds/{name}/spawn`：`{x, y, z}`，设置并保存已就绪世界的出生点。
- `POST /worlds/{name}/teleport`：`{player}`。

本模块不注册游戏命令。PlaceholderAPI 变量为 `%lbr_terrain_worlds%`（登记数量）与 `%lbr_terrain_ready%`（生成器是否就绪）。普通玩家不默认获得 Web 管理权限。

`config` 保留基础字段，可另传 `advanced` 对象；高级键使用上游的完整路径，例如 `"continents.river_ice": true`。省略的高级字段补为默认值，未知字段或超出范围的值会被拒绝。种子应传十进制字符串，不能传可能丢失精度的 JavaScript 数字。

出生点三项坐标均须为 JSON 整数，不能传字符串或额外字段。X、Z 范围为 `-29999984–29999984`，Y 范围为 `minY + 1` 至 `maxY - 2`（`maxY` 是世界高度上界，不包含在可用方块范围内）。Y 表示玩家脚部位置，下面必须有实体地板，脚部与头部须可通行且无液体或危险方块；检查通过后调用世界保存，并写入 `terrain.spawn` 审计。

## 移植范围

来源固定为官方模组 `tectonic-3.0.29-fabric-26.3.jar`，SHA-512、来源、MIT 署名与提取脚本位于 `src/main/resources/upstream/`。构建资产只含 Tectonic 的 MIT 内容；原版密度与材料规则从正在运行的 Paper 自带资源读取。

已接入的原生生成行为：

- 将配置常量、配置噪声和配置限幅解析为各世界独立的生成图，保留配置噪声的上游浮点运算与实验采样顺序。`parameter/` 噪声保留独立参数，同时使用上游的原版名称种子别名；山脊别名为 `minecraft:ridge`。
- 山地表面使用上游坡度范围条件，分别检查 X、Z 的绝对表面梯度；不再替换为原版 `steep`。超平滑开关使用官方覆盖资源。
- 地下河荧光地衣、灯笼与悬链、雪地地下河结冰使用原生 feature 和上游密度筛选。结冰识别 `c:is_snowy` 标签或已知原版雪地群系；这些装饰仅接入本模块生成器。
- 矿物修正选项采用官方 12 项矿物/砂砾放置覆盖，并按可用高度区段计算放置次数。雕刻器开关控制官方覆盖涉及的原版 `cave`、`cave_extra_underground`、`canyon`。
- 装饰、矿物和雕刻器设置按世界生成器安装，不改写公共生物群系注册项。其余原版生物群系、结构与装饰流程继续由 Paper 执行。

固定版本存在两处配置行为：`spaghetti_enabled` 未被上游配置取值函数读取，实际恒为零；`alternate_continents_scaling` 未被使用。界面不提供这两个无效开关，并保留实际行为。有效的替代侵蚀缩放开关在上游同时影响大陆和侵蚀噪声，本实现保持这一点。

尚未移植的行为：

| 项目 | 当前边界 |
| --- | --- |
| 雪线与温度偏移 | 未实现 `general.snow_start_offset` 及其温度 Mixin；普通官方预设值为 128，极限地形为 512 |
| 海底神殿偏移 | 未实现 `oceans.monument_offset`，官方预设值为 -30；结构使用 Paper 原生定位 |
| 移除冰冻海洋结冰 | 未实现 `oceans.remove_frozen_ocean_ice`，不提供该开关 |
| 旧区块混合兼容 | 未复制跨配置区块混合元数据与相关存档兼容 Mixin，不支持改造既有世界或修改已建世界参数 |
| 游戏命令 | 未移植 `/tectonic debug` 或八类 `/tectonic locate` 地形查找命令 |

因此不宣称与模组全部行为逐项相同，也不保证同种子与模组逐方块一致。生成图首次编译与核对仍在主线程完成；大高度的 CPU、内存和视距成本需在目标机器上验证。

`tools/terrain-native-probe/` 和 `tools/verify-terrain-native.mjs` 是独立测试服验收工具，不打包进 LunarCore。真实玩家客户端及目标服负载验收仍须单独完成。

## 验证范围

Java 回归测试覆盖参数与预设、精确种子、目录保护、创建意图写入失败后的恢复、固定资源校验、高级参数与覆盖资源、坡度与噪声采样、原生 codec 和压缩 NBT 重读，以及各生成器独立的装饰设置。可从仓库根目录运行 `.\gradlew.bat :lbr-terrain:test`；使用本地 Paper 时追加前述开发包参数。

前端回归测试覆盖响应合同、64 位种子、高级参数与预设、非法高度与路径及中英文词典。`tools/verify-terrain-ui.mjs` 使用模拟 API 检查浏览器交互，结果位于 `artifacts/terrain-native/`。

用户指定的现有 `E:/LBR-Test-26.3` 测试服已生成并保存两个 1024 总高度世界。使用 `tools/terrain-native-probe/offline/TerrainRegionRead.java` 以只读方式打开 MCA，经 Paper 原生 `RegionFileVersion`、`NbtIo` 与 `SimpleBitStorage` 解码，七个抽查区块均为 `minecraft:full`。以下坐标是已保存区块内的指定列；表中高度是该列最高非空气方块，不代表整片区域的最高山峰。

| 世界 | X、Z | 最高非空气方块 | 该处生物群系 |
| --- | --- | --- | --- |
| tectonic | -640、-1408 | Y343，薄雪 | grove |
| tectonic | 1344、-4160 | Y108，橡树树叶 | jungle |
| tectonic | 1408、-2688 | Y94，短草 | plains |
| tectonic | 8384、6144 | Y112，沙子 | desert |
| tectonic | 16256、-5952 | Y144，草方块 | meadow |
| tectonic | 23663、-16746 | Y376，石头 | stony_peaks |
| worldtext | -29791、-30831 | Y474，薄雪；下面 Y473 为雪块 | jagged_peaks |

`tectonic` 的 `(-640, -1408)` 所在区块有 2315 个水方块，分布在 Y54–129，其中 765 个位于 Y60–64；这些水方块同列至少四格以上存在非空气、非水、非熔岩方块。该统计证明存档中的水分布，不单独证明地下河形态。抽查区块中能读到荧光地衣，但原版也会生成它，不能仅凭方块存在归因于 Tectonic 装饰；所有样本中的普通 `lantern` 与 `iron_chain` 数量均为零，灯笼与悬链尚无完整区块实测证据。完整原始结果位于 `artifacts/terrain-native/region-proof-tectonic.json` 与 `region-proof-worldtext.json`。

地形查找条件名称不保证该列为同名生物群系。恶地峡谷与高原目前只有原生 codec 和有限噪声采样覆盖，未确认代表性完整区块。

实服出生点接口已验证两个世界的安全位置，正确请求返回 200，小数坐标与悬空位置返回 400，拒绝后出生点不变；记录位于 `artifacts/terrain-native/live-spawn-proof.json`。实际 WebUI 已将在线玩家传送到 `worldtext` 的 `(-29791, 474, -30831)`，服务端回读玩家世界与坐标吻合，游戏模式和飞行状态未改变。客户端视觉效果和目标服负载仍须单独验收；模拟接口、噪声采样及存档读取均不能替代这些验证。
