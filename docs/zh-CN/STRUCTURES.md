# YUNG’s 结构美化

[English](../en-US/STRUCTURES.md) | [安装](INSTALL.md) | [验证记录](STRUCTURES-VALIDATION.md)

在 **服务器 → 服务器操作 → 结构美化** 中，为九类结构分别选择原版或 YUNG’s：矿井、地牢、要塞、沙漠神庙、丛林神庙、女巫小屋、海底神殿、下界要塞、末地岛。客户端不需要模组或额外资源包。

## 安装与设置

1. 停服，把同次构建的 `LunarCore-<版本>.jar` 和 `LunarCoreStructures.jar` 放入 `plugins/`。
2. 使用 Java 25、Paper 26.3 启动。结构插件是独立 Paper 插件，不要放进 `plugins/LunarCore/modules/`。
3. 选择“全服默认”或具体世界。世界默认继承全服设置，关闭继承后可独立选择；重新开启继承会移除该世界的覆盖设置。
4. 保存设置并完整重启。页面分别显示当前方式和待生效方式。仅保存不会切换运行中的生成器。

本地移植构建尚未发布到上游模块市场。使用领地、世界管理或宏伟地形模块时，也请停服后用本包 `modules/` 中同次构建的对应 JAR 更新，避免混用旧版接口实现。

初次安装全部关闭。开关影响后续生成；已经开始生成或建成的结构会保留。已经建立的美化末地会继续维护其召龙、复活与传送门行为。

本次范围是九个 Better 结构项目；Bridges、Extras、洞穴改造和 Create 等其他模组的可选联动不启用。地牢沿用上游默认设置，下界小地牢默认关闭。

## 覆盖原有结构

“覆盖原有结构”默认关闭。开启并重启后，系统在目标世界进入维护状态时扫描已有区域，先在临时世界重放原版与替换结果，再决定能否覆盖。

系统只比对并写入新结构实际改动的方块及其相邻方块，范围内其他方块保持原样。这些位置与原版重放不一致、容器被动过、与领地相交、领地数据未就绪、扩展范围尚未生成或超出处理上限时，会跳过并显示原因。写入时不触发方块更新，陷阱不会被点燃，沙子不会掉落，旧箱子的物品也不会散落。

植物、水流、积雪、苔藓变体、栅栏连接、矿石与岩石边界属于自然差异，不算冲突。原木、缺失的方块和其他种类的方块仍是冲突，所以树木密集的区域常被跳过。

改动范围内的野生生物和原版生成的实体（女巫、远古守卫者、运输矿车等）会被替换，原实体写入备份。驯服、命名、拴绳、装鞍、桶装、人工繁殖、村民、傀儡、带命令标签或插件数据的实体，以及不属于原版重放的实体（玩家放的盔甲架、矿车，被打开过的运输矿车），会让该结构被跳过。掉落物、经验球和箭不影响判定。

单个操作最多处理 256 个区块。原版小地牢需要刷怪笼类型、房间和原版重放结果共同匹配，不能仅凭刷怪笼替换。已有末地岛缺少可验证的完整龙战历史时保留原样；这不是强制重置末地的工具。

维护期间禁止进入目标世界，并暂缓新玩家登录。取消会等待当前结构完成或回滚；必要的恢复不能取消。已完成或取消的同一修订不会每次重启重复扫描，更改并保存设置会安排新一轮检查。

## 备份与恢复

配置位于 `plugins/LunarCoreStructures/structures.json`。操作目录 `plugins/LunarCoreStructures/structure-backups/<操作编号>/` 包含覆盖前后区块、实体数据、校验值、处理范围和日志。

备份写入成功后才修改世界。中断的写入会在下次启动优先回滚，即使覆盖开关已经关闭。恢复完成前不会允许玩家进入。若显示“需要恢复备份”，保留操作目录，恢复缺失或损坏的备份文件后重启；不要删除日志或手动改成完成状态来绕过恢复。

关闭开关不会删除建筑或自动改回原版。使用过本插件的存档需要保留插件以读取相应结构数据；不支持热卸载、插件管理器重载或 `/reload` 切换生成器。日常全服备份应包含世界、LunarCore 数据和结构插件数据目录。

## 权限与兼容

查看、保存、取消使用现有 Web 权限 `core.server.manage`。保存会写入审计；配置冲突会拒绝保存，需要刷新后再修改。

适配面向 Paper 26.3 的原生噪声世界和 LunarCore 宏伟地形。超平坦和插件生成器的世界不受结构设置影响，继续使用原有生成方式，页面会显示提示。无法重放的旧生成参数会保守跳过。Folia、Fabric、NeoForge 不属于运行平台；实测构建和验证边界见验证记录。
